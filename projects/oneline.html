01 / THE PROBLEM

一次报销，背后是一整条流程

整理本周发票看起来只是一个小任务，实际却需要查找文件、筛选日期、重命名、汇总金额、准备附件并核对邮件。用户在软件之间切换，也在反复维护任务上下文。

“把下载目录里本周的发票整理好，生成报销清单，并发给财务。”

操作负担

查找、复制、重命名和录入反复发生，容易遗漏或填错。

流程管理负担

用户还要记住做到哪一步、判断下一步、核对结果并处理异常。

为什么从发票场景开始

目标明确、重复劳动多，文件—表格—邮件覆盖一条跨软件任务链；文件数量、金额、附件和发送状态可以逐项检查，发送节点也能展示用户控制权。

这是基于场景分析提出的需求假设，尚未经过正式用户访谈验证。

02 / PRODUCT JUDGEMENT

承担中间步骤，保留关键决定

产品判断交互如何体现希望解决什么
先确认理解展示任务对象、交付物、计划与确认点在执行前发现目标或范围偏差
过程按需展开默认展示当前进展，详细记录可以展开降低持续监督负担，同时保留追溯能力
在发送前暂停邮件准备好后展示收件人、主题与附件让用户针对具体结果作决定
准确反馈结果分别呈现已发送与保留草稿说明目标是否完整达成，以及已交付的价值
  1. 01描述目标
  2. 02理解与规划
  3. 03执行任务
  4. 04必要确认
  5. 05交付结果

原型的完整发送路径包含提交目标、开始执行与确认发送三个主要点击。“用户介入 1 次”指执行启动后的关键发送决策。

03 / AGENT DESIGN

用可观察的结果判断完成

LLM 理解目标并生成计划，执行器完成实际操作；Observer 读取执行前后状态，Verifier 根据证据检查结果。风险与授权在动作发生前判断。

理解与计划：提取对象、时间、规则、收件人与交付物，检查信息和权限，定义步骤及成功条件。

执行闭环：读取环境 → 检查风险与授权 → 定位对象并执行 → 再次观察 → 检查成功条件 → 保存进度。

遇到异常：在上限内重试、重规划，或等待用户处理；发送结果未知时先核对记录，避免重复发送。

自主程度何时采用
自主执行目标明确、已获授权、容易恢复的读取、复制和清单生成
关键节点确认对外发送、覆盖文件或删除重要资料前，展示对象与影响
澄清或停止联系人不唯一、缺少权限、环境无法可靠操作或风险超出范围

本节描述目标运行方案。真实执行、异常恢复与断点续跑尚未接入当前原型。

04 / WHAT EXISTS

当前成果与实现边界

已有交付

五阶段交互原型；文件、表格和邮件的模拟进度；执行记录；停止任务；发送确认与保留草稿分支；结果展示。

后续接入

真实 LLM 理解和动态规划、文件与发票处理、清单生成、邮件服务，以及真实异常检测和恢复。

原型名称：办妥界面中的文件、金额、环境状态和发送结果来自固定示例。输入新指令不会生成新的执行计划。

体验另一条分支前，可以点击原型页面顶部的“重置演示”，回到初始状态。

05 / TEST THE HYPOTHESIS

怎样证明值得委托

验证分三层：原型是否容易理解，真实执行是否可靠，用户是否减少操作与监督负担。五维框架帮助把任务成功与用户价值分别评估。

验证维度需要测量什么
完成能力全部交付是否正确，是否有遗漏或严重副作用
自主性用户操作减少程度，以及额外求助次数
可控性未授权动作、错发、误覆盖与重复发送
鲁棒性按异常类别统计恢复结果与人工介入
用户价值主动操作时间、等待体验和再次委托意愿

后续计划建立受控任务集，覆盖文件冲突、联系人歧义、未登录和发送状态未知等异常，再比较人工与 Agent 完成相近任务时的操作负担。

验证状态：方案已设计，尚无实测数据完整文档中的成功率和效率目标是拟定门槛，不能作为已达到的成果。可控性需要独立达标。
下一步优先验证什么

先接入真实文件与清单生成，再验证受控邮件发送及恢复能力；通过受控任务测试后进入用户试用。
